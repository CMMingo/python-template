# Subagents

Independent contexts the main agent can dispatch for a specific job -- cheaper, focused, and (for the read-only ones) safe to run without touching the working tree. The caller sees only a subagent's final message, so every subagent ends with the same brief report: what it did, the result, what it did not do or could not verify, and what to do next.

- **[code-reviewer](./code-reviewer.md)** (sonnet, high effort): Fresh-eyes review of a diff for correctness, security, seam discipline, and fit with `AGENTS.md`/`CONTEXT.md`/ADRs. Handed a spec path (and optionally one seam), it also checks intent and completeness: does the code do what the spec's *Implementation Decisions* say, and is anything the spec named missing. Read-only -- reports findings, doesn't fix them. Dispatched by `implement` after the seams (and per seam when the spec has three or more), and usable on its own before a commit or PR.
- **[changelog-writer](./changelog-writer.md)** (haiku, medium effort): Keeps `CHANGELOG.md` as the technical history: for each change, what changed and why, in the file's Keep a Changelog template. Cuts a release section when asked. Triggered by `/update-docs CHANGELOG.md`; never touches any other file.
- **[docs-updater](./docs-updater.md)** (haiku, medium effort): Updates one documentation file, given its path, so it describes what the project is and does now -- functionally, never as history. For the root README it keeps a simple, organized, jargon-light structure that works as the repository's starting point. Triggered by `/update-docs`; never touches `CHANGELOG.md`.
- **[debugger](./debugger.md)** (opus, high effort): The structured diagnosis loop for hard bugs and performance regressions -- repro, minimise, hypothesise, instrument, fix with a regression test -- looping through ranked hypotheses for up to two rounds before stopping to write up what was tried instead of guessing further. Deliberately a different mindset and model tier from `tdd`/`implement`: skeptical, slower, resists anchoring on the first plausible cause. Dispatched by the `diagnosing-bugs` skill (one confirmed-broken symptom at a time) or by `implement` for a failure inside the spec it is building. Can edit and run code (unlike the read-only agents above), but stops short of committing.
- **[security-auditor](./security-auditor.md)** (opus, high effort): Read-only security analysis of the code, dependencies, CI workflows and infrastructure: maps entry points and trust boundaries, then hunts for injection, leaks, broken access control, unsafe parsing, supply-chain and configuration problems, and denial of service. Reports ranked findings, each with an exploit path and a fix. Dispatched by the `security-audit` skill.
