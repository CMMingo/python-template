# Subagents

Independent contexts the main agent can dispatch for a specific job -- cheaper, focused, and (for the read-only ones) safe to run without touching the working tree.

- **[context-scout](./context-scout.md)** (haiku, medium effort): Read-only fact-finding in this repo -- code, docs, ADRs, git history. Dispatched by `grilling` (and everything that delegates to it: `grill-me`, `grill-with-docs`) whenever a frontier question needs a fact instead of a decision.
- **[code-reviewer](./code-reviewer.md)** (sonnet, high effort): Fresh-eyes review of a diff for correctness, security, seam discipline, and fit with `CLAUDE.md`/`CONTEXT.md`/ADRs. Read-only -- reports findings, doesn't fix them. Use once a `tdd` loop finishes, before commit or PR.
- **[logic-checker](./logic-checker.md)** (sonnet, high effort): Read-only pre-test check for one seam at a time -- does this implementation actually address what the spec's *Implementation Decisions* asked for, and is anything missing that the seam's own test wouldn't catch? Dispatched by `implement` per seam, before that seam's test confirms green. Different from `code-reviewer`: intent and completeness against the spec, not code quality or security, and runs earlier and narrower (one seam, not the full diff).
- **[changelog-writer](./changelog-writer.md)** (sonnet, low effort): Updates `CHANGELOG.md`'s `[Unreleased]` section from recent commits, and cuts a release section when asked. History only -- never touches README.
- **[readme-updater](./readme-updater.md)** (sonnet, low effort): Keeps `README.md` and similar docs accurate and lean -- deletes stale content as readily as it adds new content. Current-state only -- never touches `CHANGELOG.md`.
- **[commit-push](./commit-push.md)** (haiku, low effort): Stages the current changes, drafts a commit message from the diff, commits (splitting into several logical commits when the diff is large), and pushes once at the end. Triggered by the `/commit-push` skill so it's a deliberate, one-shot action -- never fires on its own. Doesn't open a PR; that's still a manual step. The `test-gate` and destructive-command guardrail hooks apply to every commit exactly as they would to you.
- **[debugger](./debugger.md)** (opus, high effort): The structured diagnosis loop for hard bugs and performance regressions -- repro, minimise, hypothesise, instrument, fix with a regression test -- looping through ranked hypotheses for up to two rounds before stopping to write up what was tried instead of guessing further. Deliberately a different mindset and model tier from `tdd`/`implement`: skeptical, slower, resists anchoring on the first plausible cause. Dispatched by the `diagnosing-bugs` skill, one confirmed-broken symptom at a time. Can edit and run code (unlike the read-only agents above), but stops short of committing.
